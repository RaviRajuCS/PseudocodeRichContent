File handling

File handling allows an algorithm to read stored data from a file or write data to a file.

PurposeSyntaxExamplesPractice & test

1 · Purpose

Files preserve data after a program ends. Text files are read or written line by line. Random files store records that can be accessed by position. Always open in the correct mode and close files when finished.

Core principle: WRITE creates a new file or replaces existing content; APPEND adds after existing content.

2 · Syntax and worked examples

Formal syntax

OPENFILE FileName FOR READ | WRITE | APPEND
READFILE FileName, StringVariable
WRITEFILE FileName, Data
CLOSEFILE FileName
EOF(FileName)
  • WRITE creates a new file or replaces existing content; APPEND adds after existing content.
  • READFILE reads the next line into a STRING variable.
  • EOF is TRUE when no more lines remain; check it before attempting another read.
  • Close files after operations. Random files use FOR RANDOM, SEEK, GETRECORD and PUTRECORD.

Worked examples with reasoning

Worked example 1 · Read every line
DECLARE LineOfText : STRING
OPENFILE "Scores.txt" FOR READ
WHILE NOT EOF("Scores.txt")
  READFILE "Scores.txt", LineOfText
  OUTPUT LineOfText
ENDWHILE
CLOSEFILE "Scores.txt"

EOF is tested before reading, so the algorithm does not attempt to read past the end.

Worked example 2 · Append a new line
OPENFILE "Log.txt" FOR APPEND
WRITEFILE "Log.txt", "New session started"
CLOSEFILE "Log.txt"

APPEND preserves existing lines and adds new data after them.

Worked example 3 · Random record access
OPENFILE "Students.dat" FOR RANDOM
SEEK "Students.dat", 4
GETRECORD "Students.dat", Pupil
CLOSEFILE "Students.dat"

SEEK positions the file pointer; GETRECORD reads the record at that location.

Common examination errors

  • Opening a file in WRITE mode when existing content must be preserved.
  • Reading without checking EOF, risking an attempt beyond the final line.
  • Forgetting to close a file.
  • Using a STRING for a random-file record that requires a matching record type.
