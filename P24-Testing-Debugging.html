Testing and debugging

Testing checks whether an algorithm behaves as intended; debugging identifies and corrects faults.

PurposeSyntaxExamplesPractice & test

1 · Purpose

Testing checks whether an algorithm behaves as required for selected inputs. Debugging locates and corrects faults. A strong test plan uses normal, abnormal and boundary/extreme data and states expected results.

Core principle: Normal data represents typical valid use. Abnormal data is invalid or outside the allowed domain. Boundary/extreme data tests limits or values close to them.

2 · Syntax and worked examples

Formal syntax

Test case = input data + purpose/category + expected result + actual result + pass/fail
  • Normal data represents typical valid use. Abnormal data is invalid or outside the allowed domain. Boundary/extreme data tests limits or values close to them.
  • A dry run or walkthrough follows the logic manually; black-box testing focuses on requirements and input/output, while white-box testing considers internal paths.
  • Syntax errors violate language rules; logic errors produce incorrect results; runtime errors occur during execution.
  • Retest after changes and include regression tests for previously working features.

Worked examples with reasoning

Worked example 1 · Boundary test
Requirement: mark is valid from 0 to 100 inclusive.
Tests: -1, 0, 50, 100, 101

-1 and 101 are abnormal; 0 and 100 are boundary-valid; 50 is normal.

Worked example 2 · Find a logic error
IF Mark > 50 THEN
  OUTPUT "Pass"
ELSE
  OUTPUT "Fail"
ENDIF

If a mark of 50 should pass, the condition is faulty; correct it to Mark >= 50.

Worked example 3 · Test a loop termination
WHILE Count < 5
  OUTPUT Count
  Count ← Count + 1
ENDWHILE

Starting Count=0 outputs 0 to 4 and terminates at 5. If the increment is removed, the loop may never terminate.

Common examination errors

  • Testing only typical data and missing limits or invalid values.
  • Recording actual output without stating the expected output.
  • Changing code but not retesting the correction.
  • Calling a wrong result a syntax error when the program runs but follows incorrect logic.

Independent practice · reveal guidance after attempting

Classify test data

For a valid age range of 0–120, classify 35, -1, 0 and 121.

Check your response: 35 normal; -1 and 121 abnormal; 0 boundary-valid.

Find the fault

A loop is intended to run 10 times but uses FOR I ← 1 TO 9. What is wrong?

Check your response: Off-by-one: only nine iterations; change upper bound to 10.

Design a test plan

Suggest normal, boundary and abnormal tests for a score accepted from 0 to 100.

Check your response: Examples: 55 normal, 0 and 100 boundary-valid, -1 and 101 abnormal, with expected valid/invalid result.

Cambridge-style examination challenge

Question: A program accepts a quantity from 1 to 50 inclusive. Give one normal, two boundary and two abnormal test values, with the expected validity for each. (5 marks)

Self-marking points:
Reveal the marking points

Normal value inside range; boundaries 1 and 50 valid; values below 1 and above 50 invalid.
