Records

A record groups related fields that may have different data types into one structured item.

PurposeSyntaxExamplesPractice & test

1 · Purpose

A record groups related fields that may have different data types under one identifier. It models an entity such as a student or product more naturally than parallel unrelated variables.

Core principle: Define the record type before declaring variables of that type.

2 · Syntax and worked examples

Formal syntax

TYPE RecordName
  DECLARE FieldName : <type>
  ...
ENDTYPE
RecordVariable.FieldName
  • Define the record type before declaring variables of that type.
  • Access individual fields using dot notation.
  • Fields can have different data types.
  • A record variable can be assigned to another compatible record variable as described in the guide.

Worked examples with reasoning

Worked example 1 · Define a student record
TYPE StudentRecord
  DECLARE Name : STRING
  DECLARE YearGroup : INTEGER
  DECLARE Active : BOOLEAN
ENDTYPE
DECLARE Student : StudentRecord

The record type groups three related fields under Student.

Worked example 2 · Set and read fields
Student.Name ← "Amira"
Student.YearGroup ← 11
Student.Active ← TRUE
OUTPUT Student.Name, Student.YearGroup

Dot notation selects the relevant field.

Worked example 3 · Array of records
DECLARE ClassList : ARRAY[1:30] OF StudentRecord
ClassList[4].Name ← "Omar"

Each array element is a complete StudentRecord; dot notation then accesses a field of that record.

Common examination errors

  • Declaring every field as a separate top-level variable when a record is required.
  • Using Student[Name] instead of the guide’s dot notation Student.Name.
  • Trying to assign text to an INTEGER field.
