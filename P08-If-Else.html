IF ... THEN ... ELSE

Selection chooses between paths based on whether a condition is true or false.

PurposeSyntaxExamplesPractice & test

1 · Purpose

Selection executes different statements depending on a Boolean condition. An IF without ELSE handles a one-sided action; IF...ELSE handles two alternative paths.

Core principle: The condition must evaluate to TRUE or FALSE.

2 · Syntax and worked examples

Formal syntax

IF <condition> THEN
  <statements>
ELSE
  <statements>
ENDIF
  • The condition must evaluate to TRUE or FALSE.
  • The THEN branch runs when TRUE; the ELSE branch runs when FALSE.
  • END IF is written as ENDIF in the Cambridge guide.
  • Test equality and boundary values carefully, especially >= and <=.

Worked examples with reasoning

Worked example 1 · Two-way pass decision
IF Mark >= 50 THEN
  OUTPUT "Pass"
ELSE
  OUTPUT "Not yet passed"
ENDIF

Mark 50 passes because the condition uses >=. Mark 49 takes ELSE.

Worked example 2 · One-sided action
IF StockLevel < ReorderLevel THEN
  OUTPUT "Reorder stock"
ENDIF

If the condition is false, no branch statement is executed and processing continues after ENDIF.

Worked example 3 · Select a fee
IF Age < 12 THEN
  Fee ← 5.00
ELSE
  Fee ← 8.00
ENDIF

Age 11 gives 5.00; age 12 gives 8.00. Check exactly where the boundary falls.

Common examination errors

  • Forgetting ENDIF.
  • Putting the ELSE branch inside the THEN branch through incorrect indentation.
  • Using > when the specification says “at least”, which includes equality.

Independent practice · reveal guidance after attempting

Boundary test

For IF Mark >= 50, state the branch for 49, 50 and 51.

Check your response: 49: ELSE; 50 and 51: THEN.

Complete a decision

Input a temperature; output “Cold” below 15, otherwise “Warm”.

Check your response: IF Temperature < 15 THEN ... ELSE ... ENDIF.

Choose IF or IF/ELSE

A program should add a bonus only if Sales > Target. Is ELSE required if nothing should happen otherwise? Explain.

Check your response: No; a single IF is sufficient when no alternative action is needed.

AS Mastery Extension · Deeper learning

This extension moves beyond recognising a statement. Students should be able to select it for a scenario, trace it, identify faulty logic, justify design choices and write a complete solution using Cambridge conventions.

Five progressive worked examples

Worked example 4 · Extension

Check an inclusive boundary

IF Mark >= 50 THEN
  OUTPUT "Pass"
ELSE
  OUTPUT "Fail"
ENDIF

Reasoning: Mark 50 passes because the comparison includes the boundary.

Worked example 5 · Extension

Validate before classifying

IF Mark < 0 OR Mark > 100 THEN
  OUTPUT "Invalid"
ELSE
  IF Mark >= 50 THEN
    OUTPUT "Pass"
  ELSE
    OUTPUT "Fail"
  ENDIF
ENDIF

Reasoning: Invalid data is handled separately from a valid failing mark.
