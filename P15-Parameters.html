Parameters and arguments

Parameters are named inputs in a subroutine definition; arguments are the values supplied when it is called.

PurposeSyntaxExamplesPractice & test

1 · Purpose

A parameter is a named input to a procedure or function. The argument is the actual value or variable supplied at the call. Passing by value gives the routine a value to work with; passing by reference allows a procedure to update the caller’s variable.

Core principle: If passing mode is not stated, Cambridge pseudocode assumes BYVAL.

2 · Syntax and worked examples

Formal syntax

PROCEDURE Name(BYVAL X : INTEGER)
PROCEDURE Name(BYREF X : INTEGER)
  • If passing mode is not stated, Cambridge pseudocode assumes BYVAL.
  • BYREF is used when a procedure must change the original variable supplied by the caller.
  • Parameters need data types and meaningful names.
  • Cambridge guidance states that parameters should not be passed by reference to a function.

Worked examples with reasoning

Worked example 1 · Pass by value
PROCEDURE AddFive(BYVAL Number : INTEGER)
  Number ← Number + 5
ENDPROCEDURE
Score ← 10
CALL AddFive(Score)

With BYVAL, the procedure’s local parameter changes; Score remains 10.

Worked example 2 · Pass by reference
PROCEDURE AddFive(BYREF Number : INTEGER)
  Number ← Number + 5
ENDPROCEDURE
Score ← 10
CALL AddFive(Score)

With BYREF, Score is updated to 15 because Number refers to the caller’s variable.

Worked example 3 · Two parameters
PROCEDURE DisplayArea(Width : REAL, Height : REAL)
  OUTPUT Width * Height
ENDPROCEDURE
CALL DisplayArea(4.0, 2.5)

The two arguments match the order and compatible types of the parameters.

Common examination errors

  • Confusing parameter names with argument values.
  • Expecting a BYVAL parameter assignment to update the caller’s variable.
  • Passing a literal as a BYREF argument when a modifiable variable is required.
  • Mismatching argument order or data type.
