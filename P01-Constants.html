Constants

Constants store values intended not to change during an algorithm.

PurposeSyntaxExamplesPractice & test

1 · Purpose

A constant gives a fixed value a meaningful name. This improves readability and makes a value easier to maintain: a tax rate or maximum number of attempts is written once as a named value rather than scattered as unexplained literals.

Core principle: Place constants near the beginning of the algorithm when appropriate.

2 · Syntax and worked examples

Formal syntax

CONSTANT <identifier> = <literal value>
  • Place constants near the beginning of the algorithm when appropriate.
  • The value must be a literal such as 6.50, 3, "N/A", or TRUE; do not initialise a constant from a variable, another constant, or an expression.
  • Use a meaningful identifier. Identifiers start with a letter and may contain letters, digits and underscores; avoid keywords.

Worked examples with reasoning

Worked example 1 · A rate used in a calculation
CONSTANT HourlyRate = 6.50
DECLARE HoursWorked : REAL
DECLARE Pay : REAL
INPUT HoursWorked
Pay ← HoursWorked * HourlyRate
OUTPUT Pay

If HoursWorked is 8, Pay becomes 52.0. The rate is named, so the calculation is self-explanatory.

Worked example 2 · A fixed attempt limit
CONSTANT MaximumAttempts = 3
DECLARE Attempts : INTEGER
Attempts ← 0

The constant names the policy. The variable Attempts can change; MaximumAttempts should not.

Worked example 3 · A text constant
CONSTANT SchoolName = "Modern English School Cairo"
OUTPUT "Welcome to ", SchoolName

The literal is a string, delimited by double quotation marks. The constant improves consistency.

Common examination errors

  • Writing CONSTANT Rate = OtherRate or CONSTANT Limit = 2 + 3: the guide specifies a literal value, not an expression.
  • Using a variable for a value that should remain fixed, or changing the constant later in the algorithm.
  • Choosing a vague name such as C when TaxRate or MaximumAttempts communicates intent.

Choose a suitable constant

A system gives every player 5 starting lives. Write the constant declaration and one output or assignment that uses it.

Check your response: CONSTANT StartingLives = 5; then Lives ← StartingLives.

Explain the benefit

Give two reasons why a named constant is better than repeating the literal 0.15 in several tax calculations.

Check your response: Readability and easier maintenance; one named value communicates meaning.

Five progressive worked examples

Worked example 4 · Extension

Use a fixed conversion factor

CONSTANT MinutesPerHour = 60
INPUT Hours
Minutes ← Hours * MinutesPerHour
OUTPUT Minutes

Reasoning: The named value communicates the fixed conversion factor.

Worked example 5 · Extension

Use constants in a pricing algorithm

CONSTANT TicketPrice = 12.50
CONSTANT DiscountRate = 0.10
Subtotal ← Quantity * TicketPrice
Discount ← Subtotal * DiscountRate
FinalCost ← Subtotal - Discount

Reasoning: For four tickets, subtotal 50, discount 5 and final cost 45.
