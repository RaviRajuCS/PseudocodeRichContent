Procedures

A procedure is a named subroutine that performs a task and can be called from elsewhere in an algorithm.

PurposeSyntaxExamplesPractice & test

1 · Purpose

A procedure groups statements under a name so that a task can be reused without duplicating its code. It supports decomposition, readability, testing and maintenance. A procedure performs an action; unlike a function, it is not used to return a value within an expression.

Core principle: A procedure definition describes what happens; CALL causes the procedure to execute.

2 · Syntax and worked examples

Formal syntax

PROCEDURE <name>(<parameters>)
  <statements>
ENDPROCEDURE
CALL <name>(<arguments>)
  • A procedure definition describes what happens; CALL causes the procedure to execute.
  • A procedure without parameters uses empty parentheses in its definition and call.
  • Parameters allow the same procedure to work with different data.
  • Keep each procedure focused on a coherent task.

Worked examples with reasoning

Worked example 1 · No-parameter procedure
PROCEDURE ShowTitle()
  OUTPUT "Student Results"
ENDPROCEDURE
CALL ShowTitle()

The definition can be reused wherever the title is needed.

Worked example 2 · Procedure with a parameter
PROCEDURE DisplayGreeting(Name : STRING)
  OUTPUT "Hello ", Name
ENDPROCEDURE
CALL DisplayGreeting("Mina")

Name is a parameter; "Mina" is the argument supplied in the call.

Worked example 3 · Decompose a task
PROCEDURE ShowResult(Score : INTEGER)
  IF Score >= 50 THEN
    OUTPUT "Pass"
  ELSE
    OUTPUT "Fail"
  ENDIF
ENDPROCEDURE

The main algorithm can call ShowResult for each score rather than repeating the decision logic.

Common examination errors

  • Defining a procedure but never calling it.
  • Using CALL for a function, which returns a value and is used in an expression.
  • Duplicating the same code instead of extracting a reusable procedure.

Use a parameter

  CALL DisplayHeading()
